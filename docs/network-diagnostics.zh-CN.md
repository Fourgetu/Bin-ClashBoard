# 连接、路由与节点检测

## 操作入口

- 连接页整合「路由 / 连接 / 日志」。默认按来源 IP 分组，显示设备名称、连接数和流量；可切回原始列表或表格。
- 设备名优先使用已有 IP 标签；可手动修改，或点击「识别设备」从已配置的 OpenClash / Nikki SSH 读取 DHCP 租约。未返回名称的设备继续显示 IP。
- 连接中的路由入口会带入访问目标及来源 IP。「规则路由」按规则顺序推演，「真实路由」来自内核连接的规则和代理链。规则集、GEO、进程等上下文不足时会明确标注待核实。
- 节点卡片右下角共用一个小框：左侧延迟（ms），右侧上次手动下载速度（Mbps），中间用竖线分隔。未测下载时右侧显示带宽图标。
- 鼠标悬停或键盘聚焦延迟只打开浮层并显示已有结果，不发起任何检测。点击节点小框中的延迟数字才重新测延迟，并显示加载状态；连续点击进行中的同一次检测会合并。进入「节点信息」或「风险评估」标签时，仅在当前会话尚未查询过对应内容时加载，已有结果或失败提示不重复查询。标题旁刷新按钮可主动重新查询当前标签。结果按后端和节点缓存，重新加载页面会开始新会话。按 ↓ 进入浮层，Esc 关闭。
- 切换标签或关闭浮层不会中断信息查询，结果继续写入对应节点的缓存。下载测速仍需手动开始，点击「停止测速」可取消；重新打开对应节点可查看结果或停止进行中的测速。

## 下载测速

仅点击「开始下载测速」发起测速，打开页面、悬停、切换标签或切换节点都不会自动下载。没有上传测速接口。

单次通过所选节点对 Cloudflare `https://speed.cloudflare.com/__down?bytes=10000000` 发起 HTTPS GET，最多下载 10 MB，传输超时 30 秒。Mbps 按接收字节和总耗时计算，包含连接建立时间；这是一项有流量上限的短测结果，不能代表持续峰值带宽。可随时停止。

检测使用独立 Mihomo 进程和仅监听本机的临时代理，不切换生产策略组。基础信息和风险并行查询；基础信息不占用独立探测队列。配置快照在内存中短时缓存 10 秒，同一后端的并发读取合并，手动刷新会绕过已完成的快照缓存；策略组当前选择仍实时读取。优先只读取目标节点所属订阅及前置代理依赖；内核不提供所属订阅时回退为完整读取。跨订阅读取以最多 4 个 SSH 通道并行进行。出口探测和手动下载仍串行排队；来自其他浏览器的探测请求会等待当前探测完成。排队时关闭请求会撤销等待项，失败也会释放位置；等待与查询合计上限 55 秒。结束或取消后清理临时进程及配置。

## 部署要求

### 桌面 Clash Mi / 其他 Mihomo 客户端

在「设置 → 后端 → 编辑后端 → 节点检测配置（桌面客户端）」导入该客户端当前使用的 Clash / Mihomo YAML，也可粘贴配置。点击「检查配置」，若存在未内嵌节点的 `proxy-providers`，为每个订阅选择其节点缓存 YAML，再点击「导入到此后端」。只导入包含 `proxies` 的节点订阅文件也可使用，但涉及前置代理时须同时包含相关依赖节点。

导入时核对节点名称是否出现在当前后端；这只能避免明显选错配置，不能证明同名节点的凭据一致。请使用客户端当前配置。客户端更新订阅、更换节点凭据或重命名节点后需重新导入。

配置按后端 UUID 和控制地址绑定，优先于原有 SSH / 全局本地文件来源。更改后端地址后必须重新导入或移除旧配置。导入和移除会清除当前浏览器中该后端的诊断缓存；其他浏览器需刷新页面。未导入配置的后端继续沿用原有读取方式。

只保存节点定义到面板服务器 SQLite 的独立表，不同步到浏览器设置快照，不回传节点密码，也不修改客户端的配置、规则或当前代理选择。页面显示导入数量和时间，可通过「移除检测配置」删除。包含节点凭据的 SQLite 应与面板数据一起妥善保管。

文件合计上限 6 MB。导入不会读取客户端文件路径，也不会自动访问订阅地址；只有订阅 URL、URI 列表或缺少节点缓存的配置需要先从客户端导出完整 YAML。外部证书文件的原有限制仍适用。风险与下载通过面板服务器上的独立 Mihomo 执行，不能访问仅在客户端电脑本机可达的入口。下载仍只在用户手动点击时执行。

需要随本次前端一起更新 Node 后端。纯静态部署仍可看内核连接、规则推演和延迟记录，但不提供节点入口解析、出口风险查询或下载测速服务。

Node 后端需能执行 Mihomo：优先使用现有 `.tools/mihomo-bin/` 内的对应平台程序，也可设置 `ZASHBOARD_MIHOMO_BIN`。节点配置来自当前所选后端的 OpenClash / Nikki SSH，或本机 `ZASHBOARD_DIAGNOSTICS_CONFIG` 指定的 Clash YAML。使用本机挂载时，配置必须与当前查看的后端一致。

支持配置内节点及 proxy-provider 的内联 payload / 已下载的 YAML 缓存。挂载配置时也需保留关联 provider 缓存文件和相对目录。此功能不负责下载订阅，也不将 sing-box 原生 JSON 转换为 Mihomo 节点。依赖远端证书文件等不可迁移节点会明确失败。

## 风险数据

首次进入「节点信息」或「风险评估」标签且没有缓存时查询，之后仅手动刷新时重新查询：先通过所选节点访问 Net.Coffee 的 trace 获取该节点出口，再由面板服务器向 Net.Coffee 查询该公开出口 IP 的情报。

- 来源：`https://ip.net.coffee`，使用其网站公开 JSON 接口 `/api/ip/lookup/{ip}` 和可选 `/api/ipv2/radar/{asn}`。
- 节点信息显示原始信任分和归属；风险卡片按原版分为 IP 情报、代理标记、人机流量估算与查询时间/完整报告。滥用等级显示中文文案（low 为「极度纯净」），悬停等级可查看数据源原始分值；未知状态保留未知提示。
- 缺失字段显示「暂无数据」，不把缺失值当作零风险。
- 人类 / 机器人比例是数据源的 ASN 级统计（当前接口为近 28 天），不是该 IP 的实测流量。
- 这些网站接口不保证长期稳定；失败时显示错误，不伪造风险结果。

## 真实路由的范围

真实路由优先展示匹配目标及来源 IP 的内核连接记录。没有进入内核的旁路流量无法从 Clash API 观察。

「检测真实访问」是面板服务器经当前内核 HTTP / mixed 端口访问公网 HTTPS 443 目标，最多读取 64 KB；它不模拟所选 LAN 设备。若内核代理入口要求认证，可设置 `ZASHBOARD_DIAGNOSTICS_PROXY_AUTH=user:password`。

探测链路只在来源地址、端口、目标和开始时间共同匹配时显示。NAT 或两端时钟偏差可能导致请求完成但无法捕获对应链路，此时不借用其他连接当作证据。

## 验证

新增后端测试覆盖设备 IP 归一化、规则不确定性、探测连接归属、风险字段缺失、独立节点配置、下载上限、TLS 校验、取消及禁止上传。前端样例验证使用模拟内核和模拟检测结果；发布前需在实际后端上核对 SSH、provider 路径及节点可达性。
